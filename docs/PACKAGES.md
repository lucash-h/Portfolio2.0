# PACKAGES

Work packages for every phase, with ownership, dependencies, and the rules that keep
concurrent agents from colliding. `CONTRACTS.md` is the interface law; this file is the
scheduling law.

## The three collision rules

**Rule 1 — one writer per file.** Not per directory. Two agents may work inside
`web/src/lib/games/connect4/` at the same time provided they own disjoint *files*. Every
package below lists its files explicitly. An agent that wants a file not on its list stops
and asks rather than taking it.

**Rule 2 — the orchestrator owns shared-edit files.** Some files are edited by everyone
and cannot be delegated:

| File | Why it is reserved |
|---|---|
| `web/package.json` | Every package wants to add dependencies. Concurrent edits corrupt it. |
| `web/src/routes/lab/+page.svelte` | The exhibit index; each game wants to add its link. |
| `web/src/app.css` (tokens) | The design system. Packages consume tokens, never add them. |
| `docs/CONTRACTS.md`, `docs/PLAN.md`, `docs/PACKAGES.md` | The law. |
| `.gitignore`, git state | Branches and commits are orchestrator-only. |

Agents report the dependencies they need; the orchestrator installs them *before*
spawning. No agent runs `npm install <pkg>`.

**Rule 3 — no barrel files.** No `index.ts` re-export files anywhere under
`web/src/lib/games/`. They are a magnet for merge conflicts and buy nothing here.

## Phase 1 — Connect 4 playable

### P1-F · Connect 4 fixtures · cheap model · READY NOW
**Owns:** `shared/fixtures/connect4_cases.json`
**Depends on:** nothing

The source of truth both implementations are tested against. Must cover: all four win
directions (horizontal, vertical, both diagonals), wins at board edges and corners, a full
board draw, near-miss patterns (three in a row that must NOT register), illegal moves into
full columns, and out-of-range columns. Minimum 60 cases.

Each case carries a move sequence, the expected resulting board, `legalMoves`, `winner`,
`isDraw`, and `winningCells`. Cases are generated by a reference implementation that ships
alongside, plus hand-written adversarial cases.

**Acceptance:** valid JSON; every case self-consistent under an independently written
checker (the orchestrator writes that checker — the agent does not verify its own output
with its own code).

### P1-A · Connect 4 engine · cheap model
**Owns:** `web/src/lib/games/connect4/types.ts`, `engine.ts`, `engine.test.ts`
**Depends on:** P0-A, P1-F

Pure functions per CONTRACTS §3. No mutation, no randomness, no I/O, no Svelte imports.
**Acceptance:** every fixture case passes; `npm run check` clean.

### P1-B · Connect 4 board UI · strong model
**Owns:** `web/src/lib/components/Connect4Board.svelte`, `web/src/routes/lab/connect4/+page.svelte`
**Depends on:** P0-A (types are contract-fixed, so it does not wait on P1-A)

Drop animation, win highlight, tier picker reading the manifest, keyboard play, touch
targets at least 44px. Respects `prefers-reduced-motion`. Uses existing design tokens only.
**Acceptance:** playable at 360px; full keyboard operation; no token additions.

### P1-C · Minimax placeholder · cheap model
**Owns:** `web/src/lib/games/connect4/minimax.ts`, `minimax.worker.ts`, `minimax.test.ts`
**Depends on:** P0-A

Alpha-beta, depth 6, positional heuristic, iterative deepening with a time budget. Runs in
a Web Worker so the board never blocks.
**Acceptance:** beats a random player 99+/100; returns within 500ms; never returns an
illegal column.

## Phase 2 — Self-play pipeline

### P2-S · Python scaffold · cheap model · READY NOW
**Owns:** `ml/pyproject.toml`, `ml/README.md`, `ml/.python-version`, package `__init__.py` files, `ml/conftest.py`
**Depends on:** nothing

Python 3.12, ruff + pytest configured, dependency groups for torch/numpy/onnx. A documented
one-command test entry point. A `fixtures_path()` helper so every test resolves
`shared/fixtures/` the same way.
**Acceptance:** `ruff check ml/` clean; `pytest ml/` runs and collects zero failures.

### P2-A · Environment + MCTS · strong model
**Owns:** `ml/connect4/env.py`, `ml/connect4/mcts.py`, `ml/conformance/test_connect4_parity.py`
**Depends on:** P2-S, P1-F

Env mirrors the TS engine exactly and is verified against the same fixtures. MCTS with
PUCT, root Dirichlet noise, temperature schedule, subtree reuse.
**Acceptance:** parity test green on all fixtures; MCTS with a perfect-play stub never
loses a won position.

### P2-B · Network + training · strong model
**Owns:** `ml/connect4/net.py`, `train.py`, `selfplay.py`, `replay.py`
**Depends on:** P2-A

Small residual CNN, policy + value heads, replay buffer, multiprocess self-play workers
with a configurable core count (the VPS must stay usable). Checkpoints at 1k/10k/100k/500k
games. Resumable.
**Acceptance:** loss decreases; 1k checkpoint beats random 95+/100; honours its core limit.

### P2-C · ONNX export · cheap model
**Owns:** `ml/export/to_onnx.py`, `ml/export/manifest.py`, `ml/export/test_export.py`
**Depends on:** P2-B

Exports to the exact CONTRACTS §3 signature and writes `manifest.json` per §5.
**Acceptance:** exported graph has the contract input/output names and shapes; torch and
onnxruntime agree to 1e-5 on 50 random boards.

### P2-D · Browser ML runtime · strong model
**Owns:** `web/src/lib/ml/session.ts`, `registry.ts`, `infer.worker.ts`, `mlTypes.ts`
**Depends on:** P0-A only — the ONNX signature is contract-fixed, so this needs no trained model

ORT Web session cache, manifest loading, worker-based inference, softmax + illegal-move
masking, graceful degradation to minimax if a model fails to load.
**Needs dependency:** `onnxruntime-web` (orchestrator installs).
**Acceptance:** loads a hand-built dummy ONNX matching the signature and returns masked
probabilities summing to 1.

## Phase 3 — Data and dashboard

### P3-A · Database + API · strong model
**Owns:** `web/src/lib/db/schema.sql`, `client.ts`, `queries.ts`, `web/src/routes/api/games/+server.ts`, `web/src/routes/api/stats/+server.ts`
**Depends on:** P0-A

Schema per CONTRACTS §6, pooled client, both endpoints per §7, rate limiting, and the
daily-rotating-salt hashing. **Raw IPs must not reach disk or logs** — this is the one
requirement that is a hard fail, not a nit.
**Needs dependency:** `pg`.
**Acceptance:** endpoints match the contract shapes; 429 fires at the limit; a grep of the
code and of sample logs shows no raw IP persistence.

### P3-B · Dashboard · strong model
**Owns:** `web/src/routes/lab/dashboard/+page.svelte`, `web/src/lib/components/EloCurve.svelte`, `WinRateBars.svelte`, `OpeningHeatmap.svelte`
**Depends on:** P0-A (response shape is contract-fixed, so it does not wait on P3-A)

Hand-rolled inline SVG charts, no chart library. Accessible in both themes, readable at
360px, sensible empty states for when there is not yet data.
**Acceptance:** renders correctly against a fixture `/api/stats` payload including the
empty case; no horizontal scroll at 360px.

### P3-C · Elo tournament · cheap model
**Owns:** `ml/tournament/elo.py`, `ml/tournament/run.py`, `ml/tournament/test_elo.py`
**Depends on:** P2-B

Round-robin between checkpoints, Elo with confidence intervals, writes ratings back into
the manifest.
**Acceptance:** known-outcome synthetic input produces expected ratings; ladder is
monotonic for genuinely stronger checkpoints.

## Phase 4 — Racer playable

### P4-A · Physics + track · strong model
**Owns:** `web/src/lib/games/racer/types.ts`, `physics.ts`, `track.ts`, `physics.test.ts`, `shared/fixtures/racer_trace.json`
**Depends on:** P0-A

Implements CONTRACTS §4 exactly — the constants, the twelve-step update in order, `wrapPi`
as written, raycasting, lap validation. Generates the golden trace fixture that Phase 5
ports against.
**Acceptance:** 1000 runs of the same input produce bit-identical output; trace committed;
a deliberately reordered update is shown to break the test (proving the test has teeth).

### P4-B · Canvas + input · strong model
**Owns:** `web/src/lib/components/RacerCanvas.svelte`, `web/src/routes/lab/racer/+page.svelte`
**Depends on:** P0-A

Fixed-timestep accumulator loop with interpolated rendering, keyboard + touch, HUD, lap
timer, ghost rendering hook for Phase 5.
**Acceptance:** 60fps on a mid-range laptop; physics rate independent of frame rate;
playable on touch.

### P4-C · Tracks · cheap model
**Owns:** `web/static/tracks/*.json`, `web/src/lib/games/racer/validateTrack.ts`, `validateTrack.test.ts`
**Depends on:** P0-A

Three tracks of varied difficulty plus a validator (closed loop, no self-intersection,
corner radii navigable at the model's grip).
**Acceptance:** all three validate; all three are completable.

## Phase 5 — Neuroevolution ghosts

### P5-A · Python physics port · strong model · highest risk in the project
**Owns:** `ml/racer/sim.py`, `ml/conformance/test_racer_parity.py`
**Depends on:** P4-A, P2-S

Ports the physics to Python and proves it faithful against `racer_trace.json` to 1e-9 per
tick. Written *before* any training code depends on it.
**Acceptance:** parity to 1e-9 across the full trace; float64 throughout; no `fmod`.

### P5-B · Evolution · strong model
**Owns:** `ml/racer/{net,evolution,train}.py`, `ml/export/racer_onnx.py`
**Depends on:** P5-A

Evolution strategy over a tiny MLP, parallel population evaluation, per-generation
checkpoints, export to the CONTRACTS §4 signature.
**Acceptance:** best lap improves monotonically; exported ghost completes a lap in-browser
and recovers from a collision.

## Phase 6 — Human move prediction

### P6-A · Human model · strong model
**Owns:** `ml/human/{dataset,train,export}.py`, `web/src/lib/ml/humanPredict.ts`, `web/src/lib/components/PredictionOverlay.svelte`
**Depends on:** P3-A plus enough logged games (target 5,000+)

## Integration gates

After each phase's packages land, the orchestrator — not an agent — does the wiring that
crosses ownership boundaries: adding exhibit links to `web/src/routes/lab/+page.svelte`,
installing declared dependencies, running the full `docker compose up` verification, and
reviewing every diff against `CONTRACTS.md`. Phases do not advance on an agent's own
say-so that it is done.
